# Brumavale implementation contract

Original Portuguese sandbox RPG; standalone Command Bar installer. No external assets.

Installed hierarchy:
- ReplicatedStorage.Brumavale: Config (ModuleScript), Action (RemoteEvent), State (RemoteEvent), GetState (RemoteFunction).
- ServerScriptService.Brumavale: Main (Script), World (ModuleScript), Economy (ModuleScript), Profiles (ModuleScript).
- StarterPlayer.StarterPlayerScripts.BrumavaleClient (LocalScript).
- Workspace.BrumavaleWorld: TerrainParts, Decorations, Resources, Enemies, Stations, Portals; SpawnLocation named TownSpawn.

Config is plain Lua, no Roblox types. Config.Items keyed by id: name, kind (resource/weapon/armor/consumable), tier, buy, sell, weight, damage? defense? heal?. Item ids: wood, stone, fiber, ore, hide, crystal, plank, ingot, cloth, sword1, sword2, sword3, armor1, armor2, potion. Config.Recipes keyed by output id: ingredients map, amount, fee, level. Config.Regions array: id, name, center={x,y,z}, size, safe, level, color={r,g,b}. IDs town (0,0,0), meadow (0,0,270), forest (270,0,0), quarry (-270,0,0), ruins (0,0,-270). Each size 240. Ground top y=0. Config.Enemies keyed slime/wolf/bandit/guardian: name, health, damage, speed, xp, silver, loot={item=count}, aggro, respawn. Config.Nodes keyed tree/rock/fiber/ore/crystal: name, item, amount, respawn, xp, color. Config settings: StartingSilver, Capacity, MarketTax, MaxListings, DataStoreName, SaveInterval, ProfileLeaseSeconds. Config.LevelForXP(xp), Config.XPForLevel(level).

Profiles module owned by backend agent, server-only. Economy module owned by root, pure Lua API: NewProfile(), Sanitize(raw), Weight(profile), CanAdd(profile,item,count), Add(profile,item,count) -> ok,message; Remove(...); Buy(...); Sell(...); Craft(profile,recipe,count); Equip(profile,item); Consume(profile,item) -> ok,message,heal; Grant(profile,loot,silver,xp) -> ok,message; Stats(profile) -> {damage,defense,maxHealth,level}; Quest(profile) -> {id,title,description,current,target,rewardSilver,rewardXP,complete}; ClaimQuest(profile) -> ok,msg. Profiles contain silver,xp,inventory map,equipment={weapon,armor},stats={gathered,kills,crafted},questIndex. Item counts include equipped copies (cannot remove last equipped item). All mutable economic calls have strict positive integer/known ID checks and no partial changes on failure. Capacity is weight. Consumables heal only on explicit use. Quests linear milestone sequence. Runtime server owns stats increments and inventory updates; Add/Remove/Grant don't increment stats.

Client action protocol: Action:FireServer(action,payload table). Actions: attack {target=enemy Model, skill="basic"|"cleave"}; gather {node=resource Model}; buy/sell {item=id,count=int}; craft {recipe=id,count=int}; equip/use {item=id}; claim {}; travel {region=id}; list {item=id,count=int,price=int PER UNIT}; buyListing/cancelListing {id=string}. Numeric counts bounded <=99, prices <=100000. Server validates proximity, cooldowns, instance ownership, health and payload. Interactions stations <=18 studs; resource <=14; basic attack <=15; cleave <=18. Rate limiting required.

State snapshot sent after mutation and GetState invoke: {silver,xp,level,capacity,weight,inventory,equipment,stats,quest,market={listings array},persistent=bool,region=region id,damage,defense,maxHealth}. Listing {id,item,count,price,sellerId,sellerName}. State:FireClient(player,snapshot,message?) . State may send nil,message for toasts. Optional State fourth? DO NOT depend on extra arguments. Server can set player attributes Region, ProfileReady, PersistenceEnabled. Client handles nil snapshots. Optional OpenPanel player attribute? Instead world ProximityPrompt client handles station interactions opening panels locally.

World.Build() idempotently returns Workspace.BrumavaleWorld, creates only own namespace, refuses incompatible existing namespace, never clears other user objects. World uses config ReplicatedStorage.Brumavale.Config. Resources are Models with PrimaryPart and attributes NodeType, Available=true; visible low-poly resource models and ProximityPrompt named GatherPrompt on PrimaryPart. Enemies Models PrimaryPart anchored root, attributes EnemyType, Health, MaxHealth, Alive=true; overhead health BillboardGui supported. Server moves anchored models via PivotTo, sets health/name labels. Stations are Models PrimaryPart with Station attribute shop/craft/market/quest, ProximityPrompt named StationPrompt; at town within ~60 studs of spawn. Portals Models PrimaryPart with Region target id, TravelPrompt, situated in town AND return portals in each region. Config region center supports travel destination at center+Vector3(0,5,20), safe arrival. World creates decorative borders/bridges so walking is possible. Keep spawn/arrival coordinates clear. Main connects GatherPrompt, TravelPrompt, quest prompt? Client station prompt handles opening; server also accepts explicit gather/travel actions. Client should not double-send gathers already handled on server prompts.

World.Build generates enemies with only primitive anchored parts, no Humanoid; server combat owns HP. Enemy spawn radius e.g. 65-100 from center, no enemies at arrival. Use CanCollide=false on mob pieces. Nodes have available attr; server handles cooldown visual transparency and prompt enabled. All interaction uses actual primary part position. No unsafe require(assetId), loadstring, HTTP downloads, account IDs or secrets. No global Lighting changes without installer backup.

Client original polished dark navy/gold/teal Portuguese UI: compact top HUD, quest card, bottom ability bar, responsive tabs (inventory, craft, merchant, market, world, help); selection + action buttons. Isometric camera toggle V, default Roblox camera to keep movement mobile friendly. I inventory, C craft, M map, Q cleave, R potion, E default ProximityPrompt. Left click enemy basic; touch attack button nearest. Client may locally show selection ring, hit effects from Health changes. Server authoritative. UI must not block normal movement on small screens.

Persistence: Studio default ephemeral (no API required); published servers DataStore with lease ownership, validated loaded fields, autosave, PlayerRemoving and BindToClose. Never overwrite persisted data after a read/load failure. Session market uses escrow and returns listings when seller leaves; document no global market, no crash-safe two-account transaction guarantees. No need networking or paid API for install. Economy unit tests and Luau compile/static checks outside Studio; runtime verification must be explicitly reported unrun if Studio unavailable.
